#### 第一层:你在问什么

我猜:

- 你的发言**结构清晰**吗?(还是想到哪说到哪)

#### 第二层:几个常见模式 + 你的现状

| 模式 | 描述 | 这是你吗? |
|---|---|---|
| **隐形人** | 全程不发言,等别人推进 | ⬜ |
| **附和者** | 主要发言是"对对对" "我同意" | ⬜ |
| **细节党** | 容易陷入实现细节,跟不上架构层面的讨论 | ⬜ |
| **反驳者** | 习惯先质疑,容易显得 negative | ⬜ |
| **结构化表达者** | 发言开头先说 "我有 3 个观点,第一..." | ⬜ |
| **决策推动者** | 每次都问 "那我们决定是 A 还是 B?谁来做?什么时候?" | ⬜ |

> ⭐ 最理想的状态是 **结构化表达者 + 决策推动者** 的组合 —— 这是"组长"的发言模式。

#### 第三层:行动建议

**如果你是隐形人 / 附和者**:
- 每次会议**强迫自己发言至少 1 次**,内容可以是:
  - 重复对方观点+确认("我理解你说的是 X,对吗?") —— 这至少表明你在听
  - 提一个具体问题("X 这块,Y 场景下怎么处理?") —— 显示你想得深
  - 提供一个事实("我之前看代码,这块是 Z 实现的") —— 提供别人没有的信息

**如果你是细节党**:
- 在开口前,先问自己: **"这个细节,影响这次会议的决策吗?"** 不影响就**不要在会上讲**, 会后再说。
- 训练自己**先讲结论再讲细节**(BLUF: Bottom Line Up Front)

**如果你想往结构化表达者走**:
- 发言前在心里默念 3 个字:**目标 / 论据 / 结论**
- 比如:**"目标我想确认是 X(目标)。我看到 A B C 三个迹象(论据)。所以建议我们 D(结论)。"**
- 一开始很别扭,3 个月后会变成肌肉记忆

**如果你想往决策推动者走**:
- 每次讨论快结束时,**主动问 3 个问题**:
  1. 我们今天的决议是什么?
  2. 谁来执行?
  3. 什么时候 review 进展?
- **这是项目经理 / 组长的事**,但谁先做谁就被记住
