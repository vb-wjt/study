# 工作



## 开发流程

1. 需求下发/确认 (Rally Software 上收到 Offering 团队/产品经理的需求)

2. 产品经理进行需求澄清

3. UI 设计师阅读 User story, 开始设计原型图 (Figma)

4. 前后端开发阅读 User story, 了解需求

5. UI、前后端开发、测试、产品经理进行 UI 评审

6. 前后端技术预研，出设计文档

7. 测试编写测试用例

8. 设计文档评审，测试用例评审

9. 前后端开发，联调，自验，跑测试用例

10. 功能转测，测试验证，提 bug 单

11. 开发修复 bug，回单，测试进行回归测试

12. 开发，测试进入 性能测试，PIT 测试

13. 测试进行系统测试

14. 代码合入主分支，打 release, 开发阶段结束

15. 部门项目总结会，哪些方面进步，有哪些不足，是否有好的方式/方法/工具等？

16. 其他部门负责评审，过 gate 阶段，发布到市场等

17. 结束



## 经验

1. 有哪些产品，使用对象是谁，用来解决哪些具体问题？

2. 开发一个功能:  可以怎么做？为什么要这样做？之前的做法有没有问题？是否可以改进？会遇到什么难题，怎么解决？

3. 变动/重构代码:  是否合理？影响范围？当前和后续收益？后续维护难度/成本？需要的工作量？是否会影响项目进度？

4. 用哪些合适的技术来实现哪些功能？怎么实现的？





## 学习

1. 业务:  接触到的业务，背景，是什么，有哪些相关联的业务

2. 技术:  技术预言，快速响应需求，学习，严格要求代码(评审， review， 总结)

3. 沟通:  团队沟通，综合型，国际化；在加入自己的思考见解后，有问题及时询问

4. 任务：不阻塞，有问题及时咨询/抛出，勤奋

5. 成长:  技术，沟通，团队
